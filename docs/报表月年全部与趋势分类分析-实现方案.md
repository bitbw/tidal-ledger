# 报表月年全部与趋势分类分析实现方案

> 版本：v1.0｜日期：2026-08-28  
> 参考：挖财“趋势图、结余趋势、大类、小类、分类流向、流水明细”截图，以及当前潮汐账本的 Neon、Drizzle、分类层级和流水结构。  
> 目标：报表只支持 **月 / 年 / 全部** 三种时间范围，并提供 **趋势 / 大类 / 小类** 三个分析页；所有图表和列表都可进入对应范围的真实流水明细。

## 1. 范围与基本口径

### 1.1 本次实现范围

| 模块 | 本次实现 |
| --- | --- |
| 时间范围 | 月、年、全部。全部指当前账本最早一笔未删除流水至当前时刻。 |
| 分析维度 | 趋势、大类、小类。 |
| 趋势指标 | 收入、支出、结余。 |
| 分类指标 | 支出、收入、大类流向；小类页结构与大类页一致。 |
| 下钻明细 | 点击趋势的任一周期项、分类列表项、饼图扇区或流向项，打开对应过滤条件的流水明细。 |
| 数据来源 | Neon 服务端聚合；不再使用 `GET /api/ledger` 的最近 300 笔流水做报表计算。 |

### 1.2 不在本次范围

- 成员、商家、标签、账户等多维筛选；导航占位不开放实际筛选。
- 自定义日期范围、按周分析、导出、预算对比。
- 点击流向图后做跨分类交叉关系分析；首期流向图的点击只进入该分类对应的流水明细。
- 图表库引入不是前置条件；可用原生 SVG/现有 React 组件实现，优先保证数据口径和交互。

### 1.3 统一统计口径

所有报表查询固定满足：

```text
book_id = 当前登录用户可访问的账本
deleted_at IS NULL
transaction_type IN ('income', 'expense')
```

- `income` 计入收入。
- `expense` 计入支出。
- `transfer` 不进入收入、支出、结余趋势和分类图。
- 金额在 API 与数据库使用整数分（`*_cents`），仅在 UI 层转为元并格式化。
- 当前产品按 `Asia/Shanghai` 划分自然日、月、年；避免 UTC 边界导致月末/年末归属错误。

## 2. 页面结构

```text
报表
├─ 时间范围：全部 | 年 | 月
│  ├─ 月：选择 YYYY-MM
│  ├─ 年：选择 YYYY
│  └─ 全部：无日期选择，覆盖首笔流水至现在
│
├─ 分析页签：趋势 | 大类 | 小类
│
├─ 趋势页
│  ├─ 收入趋势
│  ├─ 支出趋势
│  └─ 结余趋势
│
├─ 大类页
│  ├─ 大类支出
│  ├─ 大类收入
│  └─ 大类流向
│
└─ 小类页
   ├─ 小类支出
   ├─ 小类收入
   └─ 小类流向
```

报表主界面不再使用当前的静态/浏览器聚合示例数据。接口返回空数据时，三个页签都展示明确的空状态，而不是展示虚构图表。

## 3. 时间范围与时间桶

### 3.1 范围定义

| 范围 | 选择值 | 查询区间 | 趋势图时间桶 | 下方列表展示最近 3 条 |
| --- | --- | --- | --- | --- |
| 月 | `YYYY-MM` | 当月 1 日 00:00 至下月 1 日 00:00 | 按天 | 有真实流水的最近 3 天，倒序。 |
| 年 | `YYYY` | 当年 1 月 1 日至次年 1 月 1 日 | 按月 | 有真实流水的最近 3 个月，倒序。 |
| 全部 | 无 | 最早流水时间至当前时刻 | 按年 | 有真实流水的最近 3 年，倒序。 |

例如，用户选择 `2026 年 8 月`：

```text
趋势曲线：2026-08-01 ... 2026-08-31（每日收入、支出、结余）
列表：有真实流水的最近 3 个日期，例如 8 月 28 日、8 月 27 日、8 月 24 日
```

“全部”的开始时间通过服务端查询当前账本最早的未删除收入/支出流水确定；没有流水时不生成伪造的年份范围。

### 3.2 结余定义

本报表中的“结余”是**所选时间桶内**：

```text
结余 = 收入 - 支出
```

不是账户累计余额，也不是跨期滚动资产余额。这样月、年、全部的收入、支出、结余口径统一，并能直接下钻到流水。

## 4. 趋势页

### 4.1 三张趋势卡片

趋势页固定展示：

1. **收入趋势**：橙色曲线、橙色面积渐变。
2. **支出趋势**：青绿色曲线、青绿色面积渐变。
3. **结余趋势**：蓝色曲线、蓝色面积渐变；每个时间桶为收入减支出。

每张卡片包含：

- 标题；
- 对应曲线与当前 hover/点击时间点浮层；
- 平均线：月显示“日均”，年显示“月均”，全部显示“年均”；
- 总结文案，例如“2026 年，收入共计 40 笔，总收入 ¥312,383.52”；
- 最近 3 个有数据的时间桶列表；
- “点击展开”可展开该范围全部有数据的时间桶。

### 4.2 趋势条目与明细下钻

点击任何趋势点或下方时间桶列表项，进入流水明细页面，并携带以下过滤条件：

| 卡片 | 过滤条件 |
| --- | --- |
| 收入趋势 | 时间桶范围 + `transactionType=income` |
| 支出趋势 | 时间桶范围 + `transactionType=expense` |
| 结余趋势 | 时间桶范围 + `transactionType in (income, expense)` |

明细页标题规则：

| 来源范围 | 点击项 | 明细标题示例 |
| --- | --- | --- |
| 月 | 8 月 15 日 | `2026年8月15日流水` |
| 年 | 8 月 | `2026年8月流水` |
| 全部 | 2025 年 | `2025年流水` |

明细列表沿用当前流水展示逻辑：分类图标、分类名、备注、发生时间、收入/支出金额；并允许点击某笔进入现有流水编辑界面。

## 5. 大类页

### 5.1 大类归属规则

当前分类模型：

| 分类类型 | 报表大类 |
| --- | --- |
| 支出小类 | 其 `parent_id` 指向的支出大类。 |
| 支出大类（历史异常/旧数据） | 作为自身大类统计，但新记账不允许直接使用。 |
| 收入单级分类 | 收入没有两级结构，因此收入的“大类”和“小类”都使用该收入分类本身。 |

因此“收入大类”和“收入小类”的统计结果相同，这是产品既定规则，不需人为再建收入父级。

### 5.2 大类支出 / 大类收入

两张分类卡片：

- **大类支出**：只统计 `expense`，按支出大类聚合。
- **大类收入**：只统计 `income`，按收入分类聚合。

每张卡片包含：

- 圆环饼图：中心显示总支出或总收入；扇区显示分类名和占比；
- 排名前 3 的分类列表：图标、分类名、金额、笔数、占比进度条；
- “点击展开”展示完整排名；
- 点击扇区或分类条目，进入“所选范围 + 收支类型 + 该分类”的流水明细。

明细筛选例子：

```text
范围：2026 年
维度：大类支出
点击：餐饮
→ 2026 年内，所有 category.parent_id = 餐饮 ID 的 expense 流水
```

### 5.3 大类流向

大类流向对应参考图中的左右对照关系，不做虚构的逐笔资金配对：

```text
左侧：收入分类及金额（橙色）
右侧：支出大类及金额（青绿色）
顶部：总收入 / 总支出
```

- 条形长度以各侧自身总额为基准；收入和支出不强行按同一比例比较。
- 默认展示每侧前 8 项；点击“展开”查看完整分类。
- 点击左侧收入项：进入所选范围内该收入分类流水。
- 点击右侧支出项：进入所选范围内该支出大类流水。
- 流向图只是“收与支结构的并列概览”，首期不声称收入可逐条追踪到某个支出分类。

## 6. 小类页

小类页的卡片结构、颜色、展开、点击下钻与大类页完全相同，区别仅在支出聚合键：

| 模块 | 大类页的分组 | 小类页的分组 |
| --- | --- | --- |
| 支出 | 支出小类的父分类（大类） | 支出小类自身 `category_id` |
| 收入 | 收入分类自身 | 收入分类自身（与大类相同） |
| 流向右侧 | 支出大类 | 支出小类 |

小类支出饼图可能项目较多：

- 图中优先标注占比高的项目，避免标签重叠；
- 完整分类和精确金额由下方排序列表承担；
- 仍默认只展示前 3 条，用户点击展开查看完整列表；
- 点击“住宿房租”“午餐”等小类，明细只包含对应 `category_id` 的流水。

## 7. 服务端报表 API

### 7.1 路由

```text
GET /api/ledger/reports?scope=month&date=2026-08
GET /api/ledger/reports?scope=year&date=2026
GET /api/ledger/reports?scope=all
```

参数校验：

| `scope` | `date` |
| --- | --- |
| `month` | 必填，严格 `YYYY-MM`。 |
| `year` | 必填，严格 `YYYY`。 |
| `all` | 不允许传 `date`，或忽略该字段。 |

未登录返回 `401`；无效范围返回 `400`；所有账本范围由 Better Auth Session 和服务端成员关系决定，客户端不传可信 `bookId`。

### 7.2 返回结构

```ts
type ReportScope =
  | { type: "month"; date: "2026-08" }
  | { type: "year"; date: "2026" }
  | { type: "all" };

type ReportBucket = {
  key: string;              // month: YYYY-MM-DD, year: YYYY-MM, all: YYYY
  label: string;            // 8月15日 / 2026年8月 / 2026年
  startAt: string;
  endAt: string;
  incomeCents: number;
  expenseCents: number;
  balanceCents: number;
  incomeCount: number;
  expenseCount: number;
};

type CategoryReportItem = {
  id: string | null;        // 大类为 parent category ID；小类/收入为 category ID
  name: string;
  icon: string | null;
  color: string;
  amountCents: number;
  transactionCount: number;
  percentage: number;
};

type ReportResponse = {
  scope: ReportScope;
  range: { startAt: string | null; endAt: string | null };
  summary: {
    incomeCents: number;
    expenseCents: number;
    balanceCents: number;
    incomeCount: number;
    expenseCount: number;
  };
  trends: ReportBucket[];
  categories: {
    major: {
      expense: CategoryReportItem[];
      income: CategoryReportItem[];
    };
    minor: {
      expense: CategoryReportItem[];
      income: CategoryReportItem[];
    };
  };
};
```

客户端由同一份返回结果渲染趋势页、大类页、小类页；避免多张图各自请求、各自计算而产生口径不一致。

### 7.3 明细接口

新增独立、可分页的明细 API，不复用“最近 300 笔”：

```text
GET /api/ledger/transactions?
  start=2026-08-15T00:00:00+08:00&
  end=2026-08-16T00:00:00+08:00&
  types=income,expense&
  categoryLevel=major&
  categoryId=<餐饮大类 ID>
```

支持的过滤项：

- `start` / `end`：必需成对出现；范围由报表卡片生成。
- `types`：`income`、`expense` 或两者。
- `categoryLevel`：`major` / `minor`；仅分类下钻时携带。
- `categoryId`：大类 ID 或小类/收入分类 ID。
- `cursor` / `limit`：使用游标分页，默认 50，最大 100。

服务端处理：

- `major + expense`：关联分类，过滤 `categories.parent_id = categoryId`；兼容历史直接使用大类的流水时可额外包含 `transactions.category_id = categoryId`。
- `major + income`：过滤 `transactions.category_id = categoryId`。
- `minor`：过滤 `transactions.category_id = categoryId`。
- 不允许客户传任意账本 ID；始终限制当前用户账本与 `deleted_at IS NULL`。

## 8. Neon / Drizzle 查询实现

### 8.1 服务端函数

建议在 `src/features/ledger/server.ts` 新增：

```ts
getLedgerReport(userId, scope)
getLedgerTransactions(userId, filters)
```

内部职责：

1. 用 `ensureDefaultLedger(userId)` 取得当前账本。
2. 根据 `scope` 和上海时区计算开始、结束边界。
3. 用 Neon/PostgreSQL 聚合趋势桶、分类金额和笔数。
4. 统一排除软删除与转账。
5. 为分类结果补齐名称、图标、颜色及百分比。
6. 空范围返回零汇总和空数组，不返回静态样例。

### 8.2 推荐 SQL 分组思路

| 数据 | 分组 |
| --- | --- |
| 月趋势 | 上海时区日期 `YYYY-MM-DD`。 |
| 年趋势 | 上海时区月份 `YYYY-MM`。 |
| 全部趋势 | 上海时区年份 `YYYY`。 |
| 大类支出 | `COALESCE(category.parent_id, category.id)`。 |
| 小类支出 | `category.id`。 |
| 大类/小类收入 | `category.id`。 |

日期计算与 `date_trunc` 必须明确时区。例如 PostgreSQL 查询中先将 `occurred_at` 映射到 `Asia/Shanghai` 再截断，不能直接依赖数据库服务器默认时区。

1. **P0：服务端数据层**

   - 实现趋势、大类、小类聚合；

3. **P2：大类页与小类页**
   - 圆环饼图、Top 3、展开；

   - 超过 300 笔流水时核对报表完整性；

   - 检查移动端图表标签拥挤、空状态、加载状态和可访问性。

## 11. 验收清单

### 时间范围

- 月、年、全部三种范围均可切换；
- 月显示按日趋势及最近 3 个有数据日期；
- 年显示按月趋势及最近 3 个有数据月份；
- 全部显示按年趋势及最近 3 个有数据年份；
- 全部开始时间等于当前账本最早一笔有效流水时间。

### 趋势

- 收入为橙色、支出为青绿色、结余为蓝色；
- 每张趋势卡的总额、笔数、平均值与明细加总一致；
- 点击趋势点、列表项均能打开正确时间范围和收支类型的流水明细。

### 分类

- 大类支出按支出父分类聚合；小类支出按小类自身聚合；
- 收入在大类和小类页均按收入分类自身统计；
- 每张分类卡默认显示 Top 3，展开后展示完整排序；
- 饼图、Top 3 条目、流向图条目都能进入正确分类明细；
- 百分比总计允许因四舍五入略有误差，但金额必须精确到分。

### 数据安全与一致性

- 账本超过 300 笔流水后，报表仍包含全部历史记录；
- 已软删除流水、转账不进入统计或明细；
- 未登录返回 `401`，用户不能读取其他账本的报表或明细；
- `npm run build` 通过；Preview Neon 中手工核对至少一个月、一个年、全部范围。

## 12. 关键决策

- 报表从浏览器聚合迁移为 Neon 服务端聚合，解决 300 笔上限与统计口径分散问题。
- “全部”按**有记录开始到现在**，而不是固定近 12 个月。
- 趋势列表展示“最近 3 个有数据时间桶”，而不是机械展示自然日/自然月/自然年。
- 收入只有单级分类，因此收入的大类与小类统计故意相同；这是数据模型决定的正确结果。
- 流向图是收支结构对照，不伪造跨分类资金因果关系。
