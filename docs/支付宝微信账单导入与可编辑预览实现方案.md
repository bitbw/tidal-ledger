# 支付宝微信账单导入与可编辑预览实现方案

> 版本：v1.0｜日期：2026-08-31
> 目标：支持用户导入支付宝、微信支付导出的 CSV/Excel/ZIP 账单，在写入账本前逐笔预览、编辑和确认。

## 1. 产品范围

采用“用户导出账单文件 → 浏览器解析 → 可编辑预览 → 服务端去重确认 → 写入账本”的方式。

本期支持：

- 支付宝和微信个人账单文件；CSV、XLS/XLSX、ZIP。
- 修改交易时间、商户/摘要、金额、收支方向、分类、备注、账户。
- 单行启用/跳过、批量选择分类、批量跳过重复项。
- 导入前显示有效、待分类、异常、重复数量。
- 导入后保留批次和逐行处理结果，可追溯来源。

不做自动登录支付宝/微信、不读取密码、不接入个人账单自动同步接口。商户对账 API 另行规划。

## 2. 预览编辑模型

解析结果统一为：

```ts
type ImportPreviewRow = {
  clientKey: string;
  rowNumber: number;
  occurredAt: string;
  merchantName: string;
  amountCents: number;
  direction: "expense" | "income" | "unknown";
  categoryId: string | null;
  accountId: string | null;
  note: string;
  externalTransactionId: string | null;
  enabled: boolean;
  duplicate: boolean;
  error: string | null;
};
```

预览表格每行可编辑：

- 时间：`datetime-local`；
- 金额：数字输入，保存为整数分；
- 收支：收入/支出切换；
- 分类：复用现有分类选择器，支出先选大类再选小类，收入选择单级分类；
- 账户：选择账本账户；
- 商户、备注：文本输入；
- 是否导入：开关或复选框。

默认分类只做辅助匹配，不覆盖用户手工修改。未知收支、金额为 0、时间无效或支出未选小类的行不能确认导入。

## 3. 前端流程

### 3.1 选择文件

继续使用现有 `parseStatementFile`。解析阶段只在浏览器执行，原始文件不上传。解析后调用服务端“重复预检”接口，标记已存在流水。

### 3.2 可编辑预览

将当前 `ImportDialog` 拆分为：

- `ImportFileStep`：选择文件和来源；
- `ImportPreviewStep`：统计卡片、筛选栏、可编辑行；
- `ImportRowEditor`：单行编辑；
- `ImportResultStep`：导入成功、跳过和失败结果。

预览页支持按“全部 / 待处理 / 异常 / 重复 / 已选中”筛选；移动端使用卡片编辑，桌面端使用表格。确认按钮显示实际选中笔数。

## 4. 服务端 API

### `POST /api/imports/check`

请求携带解析后的标准化行，不携带原始文件。服务端按当前用户账本查询：

- `bookId + source + externalTransactionId`；
- 无订单号时使用 `source + sourceRowHash`；
- 同一批次内也要去重。

返回每行的 `duplicate`、已有交易 ID 和可用账户/分类基础信息。

### `POST /api/imports/confirm`

请求携带用户编辑后的有效行和批次元数据。服务端必须重新校验：

- 登录用户和当前账本权限；
- 收支类型、金额、时间、分类层级、账户归属；
- 订单号/哈希重复；
- 行数和金额范围，防止恶意请求。

服务端事务内创建 `import_batches`、`transactions`、`import_rows`：

- `transactions.source` 使用 `wechat` 或 `alipay`；
- `externalTransactionId` 保存平台订单号；
- `sourceRowHash` 保存无订单号行的稳定哈希；
- `importBatchId` 关联导入批次；
- `import_rows.decision` 使用 `imported`、`duplicate`、`skipped`、`failed`。

返回导入数、重复数、跳过数、失败行及失败原因。

## 5. 去重与数据口径

优先级：平台订单号 > 稳定行哈希。哈希输入至少包含来源、时间、金额、收支、商户、备注；字段需先标准化空格、金额和时间格式。

退款默认按账单提供的收支方向导入，不自行抵消原消费。交易关闭、撤销、纯转账、余额变动等无法归入普通收入/支出的记录默认标记为异常，由用户选择跳过或调整后导入。

现有 `transactions` 的唯一索引可作为第一层保护，但确认接口仍需在事务中再次判断，避免并发重复导入。

## 6. 分类与账户匹配

- 分类优先级：用户上次对同一商户的选择 → 平台交易分类映射 → 默认“待分类”。
- 本期不自动创建新分类。
- 支出只允许选择可记账小类；收入只允许选择单级收入分类。
- 账户默认不指定，用户可批量设置账户；不应伪造微信/支付宝余额。

## 7. 实施顺序

1. 扩展解析结果，保留平台原始字段和稳定行哈希。
2. 新增 `check`、`confirm` API 与服务端事务导入函数。
3. 将 `ImportDialog` 改为可编辑预览，并复用现有分类选择器。
4. 增加批量分类、批量跳过、异常筛选和导入结果展示。
5. 对超过 300 笔账单做分页/分批提交，避免请求体过大。
6. 更新导入说明文档，明确支付宝和微信文件导出入口。

## 8. 验收清单

- 支付宝、微信账单均能识别来源并解析时间、金额、商户、订单号。
- 用户可以逐笔修改时间、金额、收支、分类、账户、备注和是否导入。
- 未分类、异常、无效时间和重复行不会被误写入。
- 重复导入同一文件不会生成重复流水。
- 确认导入后报表、日历、流水列表能看到新数据。
- 导入批次和逐行结果可追溯；失败行不会导致整批数据部分写入。
- Preview Neon 手工验证后再合并发布到 `main`。
