# 账单自动分类实现方案

> 版本：v1.0｜日期：2026-08-31
> 目标：支付宝、微信账单导入后自动推荐账本分类；用户始终可以在预览中修改，未命中时不自动乱填。

## 1. 范围与原则

导入仍采用“本地解析 → 可编辑预览 → 服务端确认写入”的现有流程。自动分类只负责为预览行填入推荐分类，不直接写入流水，也不自动创建分类。

推荐优先级：

1. 用户已保存的商户分类规则；
2. 支付宝/微信的交易分类映射；
3. 商户名、商品说明的关键词规则；
4. 无命中时保留“待分类”。

平台分类和关键词只能作为初始建议；用户在预览中手动改动后，以用户选择为准。

## 2. 解析结果扩展

扩展 `ParsedStatementRow`，在现有字段外保留分类判断所需的来源信息：

```ts
type ParsedStatementRow = {
  // 现有字段...
  platformCategory: string; // 如“餐饮美食”“交通出行”
  productName: string;      // 商品说明/交易描述
  rawDirection: string;     // 原始“收/支”字段
};
```

- 支付宝：`交易分类` → `platformCategory`，`商品说明` → `productName`。
- 微信：优先读取账单内的交易类型、商品或商户描述；没有则为空字符串。
- 导入预览行也携带这两个字段，但不在界面展示为必填输入。

## 3. 自动匹配规则

前端在拿到 `ledger.categories` 后立即计算 `categoryId`。不需要新增接口，分类数据已在账本首页加载。

### 3.1 标准平台分类映射

维护一个小型、可读的内置映射表，匹配现有分类的名称而非写死 UUID：

| 平台分类/关键词 | 建议支出小类 |
| --- | --- |
| 餐饮美食、外卖、美团、饿了么 | 餐饮 |
| 交通出行、滴滴、打车、地铁 | 打车/公共交通 |
| 日用百货、便利店、超市、盒马 | 日用品/买菜 |
| 医疗健康、医院、药店 | 医疗 |
| 充值缴费、电费、水费、燃气 | 水电燃气/话费 |
| 服饰装扮、迪卡侬 | 服饰 |
| 文化休闲、电影、游戏 | 娱乐 |

实际匹配时按当前账本名称查找：优先精确名称，其次允许预设同义词，例如“餐饮”可匹配“餐饮美食”。找不到对应分类则不填。

收入不按支出的大类/小类路径处理：仅尝试匹配当前收入单级分类，例如“工资”“退款”“兼职”“红包”；没有命中时保留待分类。

### 3.2 商户关键词规则

关键词匹配只在平台分类没有命中时启用。匹配文本为：`merchantName + productName + note`。规则按最长关键词优先，避免“医院”与更具体的商户词冲突。

`不计收支`、交易关闭、金额为零等现有不可导入行不参与自动分类。

## 4. 记住用户选择

第一期完成内置匹配后，新增按账本隔离的规则表，保存用户在导入预览中确认的商户分类选择：

```ts
import_category_rules {
  id, bookId, normalizedMerchantName,
  direction, categoryId,
  matchCount, createdAt, updatedAt
}
```

- 唯一索引：`bookId + normalizedMerchantName + direction`。
- `normalizedMerchantName` 去首尾空格、折叠空白、转小写；不保存订单号等易变文本。
- 用户明确修改分类并成功导入时，upsert 该规则；平台自动命中的分类不写入规则表。
- 下一次导入时，服务端批量查询本批次商户规则，返回给前端后作为最高优先级建议。

这张表需通过 Drizzle schema 和 migration 创建，并先在 Preview Neon 执行 `npm run db:migrate` 验证。

## 5. 前端与服务端改动

### 前端

- 新增纯函数 `suggestImportCategory(row, categories, merchantRules)`，返回 `categoryId | null` 和命中来源：`merchant_rule`、`platform_category`、`keyword`、`none`。
- 文件解析后、重复预检前为每行补入建议分类。
- 分类卡片可显示“已自动推荐”，但不遮挡原有的手动分类入口。
- 用户切换收支类型时重新计算建议；若用户已手动选过分类，不覆盖其选择。

### 服务端

- `POST /api/imports/check` 接收商户名和收支方向，批量返回当前账本匹配到的商户规则。
- `POST /api/imports/confirm` 继续校验分类属于当前账本；导入成功后仅对用户手动修改过分类的行更新规则。
- 所有规则查询和写入必须按 `bookId` 限制，不能用客户端传入的账本 ID 决定数据范围。

## 6. 实施顺序

1. 扩展支付宝、微信解析字段，确保平台分类和商品说明不丢失。
2. 实现内置平台分类与关键词推荐纯函数，并在预览默认填充分类。
3. 为推荐分类增加轻量提示，验证用户仍能一键修改。
4. 新增 `import_category_rules` schema、migration、预检查询和确认后 upsert。
5. 在 Preview Neon 执行 migration，导入真实支付宝和微信账单验证后发布。

## 7. 验收

- 支付宝“餐饮美食/滴滴/国网/医院”等记录能推荐到账本中存在的正确小类。
- 收入只推荐当前收入单级分类，支出只推荐可记账的小类。
- 账本没有对应分类、交易关闭、不计收支或金额为零时，不自动填分类。
- 用户在预览改过“盒马鲜生”为“买菜”并成功导入后，下次同商户导入优先推荐“买菜”。
- 商户规则不会跨账本、跨用户泄露；用户仍可覆盖任意推荐结果。
